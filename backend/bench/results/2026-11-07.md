## What the benchmark changed

The first run, before the fixes below, put a typical answer at **6.8 s** even though the fake model had finished writing it after 1.9 s:

| | Before | After |
|---|---|---|
| Answer complete, 1 conversation (p50) | 6.82 s | 1.95 s |
| Bot's own work, 1 conversation (p50) | 32 ms | 9 ms |

1. **Streamed model answers were typed out at the script pace.** The pace was 24 characters every 250 ms, so the message lagged ~5 s behind the model. Model answers now use `LiveReply(follow=True)`: each edit shows all the text that has arrived, and the last edit is made as soon as the model stops. Scripts keep the typewriter pace.
2. **The partial answer was re-formatted for Rocket.Chat on every token.** This costs O(n²), about 0.75 ms per call for a 2.6k-character answer. `LiveReply.push` now takes a function, which runs once per edit instead of once per token.
3. **Each message read `config_version` from SQLite.** The version is now checked at most once a second, since portal writes invalidate the snapshot anyway.
4. **Every commit waited for an fsync.** SQLite now runs WAL with `synchronous=NORMAL`, which is still safe against corruption.

The p95 of "own work" at 10–50 conversations (80–320 ms) does not come from slow code. It is the event loop and SQLite's single writer being shared: several turns commit, parse SSE and format at the same moment. p50 stays at 2–4 ms. If that tail matters later, the cheaper levers come before Rust:

- Batch the three commits per turn (transcript, `agent_run`, `message_log`) into one write-behind queue, so turns stop contending for SQLite's single writer.
- Run uvicorn with `--loop uvloop` explicitly. It is already picked automatically when installed.
